# 온기 (ONGI)

디지털 취약계층(고령자·장애인 등)을 위한 **AI 기반 스마트폰 접근성 도우미**.
설치된 앱을 자동 스캔해 생활 카테고리로 재구성하고, 음성 명령·단축 실행, 생활 루틴 추천,
미사용 앱 정리 안내를 제공한다. 모든 AI 추론은 온디바이스(Gemma 4 E2B)로 수행한다.

- **대회**: 2026 오픈소스 개발자대회 (접수번호 820, 팀 TSP, 일반부문·자유과제)
- **제출 기한**: 2026-08-27(목) 18:00, osscontest.kr
- **스택**: Flutter/Dart + Kotlin·Swift 플랫폼 채널 + flutter_gemma(LiteRT-LM) + Gemma 4 E2B(Apache 2.0) + speech_to_text/flutter_tts + sqflite
- **라이선스**: MIT (직접 작성 코드 — 대회 규정상 OSI 인증 라이선스 필수)

## 릴레이 접속 — 주소를 넣은 기기만 붙는다 (v0.0.25에서 해소)

**릴레이 주소는 코드에 없다.** 값은 "연결 서버 설정"(어르신 = 설정 → 보호자 정하기, 보호자 = 보호자 홈)에서만 들어오고, 비어 있으면 접속을 시도하지 않는다(재시도도 걸지 않는다). 그래서 주소를 넣지 않은 기기 — 심사위원 폰을 포함해 데모망 밖의 모든 기기 — 는 **릴레이에** 접속하지 않는다.

주의: 이것은 "앱이 아무 데도 접속하지 않는다"는 뜻이 아니다. 최초 1회 모델 다운로드(Hugging Face)는 그대로 있고, 음성인식은 OS 음성 서비스를 거친다. 보고서 문구도 그 범위로만 쓴다.

v0.0.24까지는 사내망 주소가 기본값으로 박혀 있어서, 어르신 역할을 고른 기기는 **보호자를 한 명도 등록하지 않았어도** 켤 때마다 그 주소로 접속을 시도했다. v0.0.22가 최초 연결 실패까지 재시도 대상으로 바꾸면서(그 전에는 한 번 실패하고 조용히 포기해 앱 재시작 전까지 코칭이 불가였다) 그 시도가 영구히 이어졌고, 재시도 간격 상한 5분으로 비용만 낮춰 둔 상태였다. 이제 시도 자체가 없다. 백오프 정책(`WebSocketSignaling.backoffFor`)은 주소가 있는 기기에만 적용된다.

보고서의 "출품 범위 기능은 자체 외부 서버 없이 동작"은 기능 단위로 참이다 — 앱 스캔·런처·음성·루틴·정리 어느 것도 릴레이를 쓰지 않고, 이제 주소 상수조차 없어 손으로 넣기 전에는 릴레이에 붙지 않는다. 다만 **자체 서버가 없다는 것과 아무 데도 접속하지 않는다는 것은 다르다** — 모델 다운로드는 남아 있으므로 보고서에 "외부 연결이 없다"는 식으로 넓혀 쓰지 않는다.

남은 개선안 하나: **코칭을 실제로 쓸 때만 접속** — 주소가 있어도 보호자가 등록돼 있을 때만 붙이고, 등록 화면은 진입 시 온디맨드로 연결하는 방식. 가장 정확하지만 페어링 진입 경로를 손봐야 한다. 지금 상태로 제출에 지장은 없다고 본다.

  - `startForeground` 예외를 받아 서비스가 스스로 끝나게 했다 — Android 14의 mediaProjection FGS 시작 순서 요구가 실제로 거부로 나타나더라도 통화 중 앱이 죽는 대신 "시작하지 못했어요"로 끝난다(실기기 확인은 `docs/50` §14 미결)
- 보호자 확인 창과 실제 동작의 불일치
  - 등록 요청 확인 창이 보여 준 사람과 수락 대상이 어긋날 수 있었다 — 창이 떠 있는 사이 다른 어르신의 요청이 도착하면 대기 요청이 조용히 교체되고, 창 문구는 그대로인데 `pair_ok`는 새 요청자에게 나갔다. 보호자가 A를 보고 수락했는데 B가 앵커를 얻고, A는 60초 뒤 일반 실패 문구만 봤다. 응답 대상을 인자로 고정하고, 그 사이 바뀌었으면 아무것도 보내지 않게 했다(잘못 등록하느니 실패). 밀려 들어온 요청은 따로 다시 묻는다
  - 공유 중 뒤로가기로 화면을 벗어나면 캡처와 상시 알림은 내려가는데 세션 단계가 `sharing`에 고착됐다. 다시 들어오면 "보고 있어요"가 계속 떠 있고, 공유를 되살리는 버튼은 `talking` 단계에만 있어 그 세션에서는 복구가 불가능했다 → 화면을 뜰 때 단계도 함께 되돌린다
- 그 밖
  - 역할 선택 화면이 "나중에 설정에서 바꿀 수 있어요"라고 약속하면서 바꿀 경로가 없었다. 잘못 고른 어르신은 보호자 화면에 갇혀 런처도 모델도 쓰지 못했다 → 설정과 보호자 홈 양쪽에 전환 경로 추가(역할 변경 시 시그널링 재구성 포함)
  - 화면 공유 동의 다이얼로그가 떠 있는 사이 세션이 끝나면 캡처와 상시 알림이 고아로 남았다 → 재확인 후 정리
  - 민감 화면 감시 준비가 예외로 실패하면 공유는 계속되는 fail-open이 남아 있었다 → 판정 불능이면 가린다(ADR-19)
  - OS 쪽에서 캡처가 끝났을 때의 배선(`onCaptureEnded`)을 넣었다. flutter_webrtc 1.5.2 Android가 이 이벤트를 올리지 않아 현재는 뜨지 않으며, 그 사실을 코드와 `docs/50` §14에 명시했다
- 자기검토에서 잡은 **이번 수정이 만든 회귀 7건** (수정분을 다시 3관점으로 검토한 결과)
  - **귀머거리 보호자** — `connect`가 실패 시 재시도를 예약하고 다시 던지게 바꾸면서, 그 뒤에 있던 메시지 구독이 예외로 건너뛰어졌다. 릴레이가 아직 안 뜬 상태로 보호자 앱을 켜면(데모망 밖에서는 기본 상황) 백오프가 소켓을 되살려 서버에는 보호자로 등록되지만 앱에는 듣는 사람이 없어, 어르신의 페어링·도움요청이 조용히 버려졌다. 수정 전보다 나쁜 상태였다 — 전에는 등록 자체가 안 돼 어르신이 즉시 offline 거절이라도 받았다. 구독을 연결보다 먼저 걸도록 순서를 바꿨다
  - **스테일 핸들러가 새 세션을 끊었다** — 재접속 시 등록을 지키는 `drop()` 신원검사는 넣었는데, 정리 블록이 그 결과를 버리고 파트너 해제를 그대로 실행했다. 순단→재접속으로 새 세션이 선 뒤 옛 연결이 뒤늦게 죽으면 보호자만 끊기고 어르신은 통지를 못 받아 "보고 있어요"로 남았다 — 이 정리가 막으려던 바로 그 상태다. 정리 로직을 `cleanup()`으로 빼 테스트가 실제로 타게 하고, 등록 당사자일 때만 세션을 정리하도록 게이트했다
  - **좀비 소켓 역전 레이스** — 타임아웃된 연결을 클라이언트가 닫아도, 그 핸드셰이크가 재시도 연결보다 늦게 완료되면 서버 등록을 덮어쓴 뒤 스스로 정리되며 키를 통째로 비웠다. 서버 `add()`가 밀려난 소켓을 닫도록 해 순서와 무관하게 수렴시켰다(밀려난 쪽은 끊김을 감지해 곧바로 재등록한다)
  - **재접속이 페어링 수락을 무효화했다** — 응답 자격을 `Peer` 객체에 매달아, 보호자가 확인 창을 띄운 채 자동 재연결되면 새 객체에는 자격이 없어 수락이 조용히 무시됐다. 자격을 키에 귀속(`Registry.pending_pairs`)시켜 재접속을 넘어 유지된다
  - **역할 전환이 진행 중 세션을 방치했다** — 소켓만 닫아 보호자는 늦게 알고, 감사 로그는 열린 채 남고, 단계가 `talking`에 고착돼 나중에 어르신으로 돌아와도 새 요청이 막혔다. 전환 전에 세션을 정상 종료한다
  - **비행 중인 재시도가 닫은 연결을 되살릴 수 있었다** — `_open()`이 await를 넘는 사이 `close()`나 재connect가 일어나면 늦게 완료된 옛 시도가 새 소켓을 덮어썼다. 세대(epoch) 가드를 넣어 소켓 대입 직전에 대조한다
  - **`setRole`이 저장 실패 시 영구 무반응** — 메모리를 먼저 바꾸고 저장해서, DB 쓰기가 실패하면 값은 이미 새 역할이라 중복 가드에 걸려 다시 눌러도 아무 일이 없었다(역할 선택 화면에 갇힌다). 저장 성공 뒤에 바꾼다
