## P0 — 반드시 반영 (9건)

### 1. 삼성 인터넷 실기기 스모크가 최우선 (구현 첫 2~3시간)
어르신 갤럭시의 기본 브라우저인 **삼성 인터넷에서 `intent://`가 동작하지 않는다는 보고가 다수**. 여기가 깨지면 "타일 탭 = 앱 실행"이라는 존재 이유가 무너진다.
- [ ] 삼성 인터넷·Chrome 각각에서: intent 실행 / 미설치 Play 폴백 / tel: / 홈 화면 추가 / PWA standalone 모드에서 재확인
- [ ] 폴백 체인 구현: intent 시도 → `visibilitychange`+타이머로 전환 실패 감지 → `https://play.google.com/store/apps/details?id=…`(https 링크는 전 브라우저 동작)
- [ ] UA `SamsungBrowser` 감지 시 앱별 커스텀 스킴(카톡 `kakaotalk://` 등, 사전에 스킴 열 추가)/https 앱링크 우선
- [ ] 모든 intent에 `package=` 명시(앱 선택기 원천 차단), `S.browser_fallback_url` 지정

### 2. 카카오톡 인앱 브라우저 탈출
보호자가 링크를 **카톡으로 보내는 순간** 인앱 브라우저로 열린다 — 저장소가 분리되고 PWA 설치도 불가. 전달 경로의 첫 관문.
- [ ] 인앱 UA 감지 → `kakaotalk://web/openExternal?url=…`로 외부 브라우저 강제 오픈(실기기 검증)
- [ ] 실패 시 "⋮ → 다른 브라우저로 열기" 그림 안내 전체 화면 오버레이, 해제 전 온보딩 진입 차단

### 3. 복구 링크(구성 공유) — 보호자 대리 설정과 소실 복구를 한 방에
localStorage 단일본은 (a) 보호자 기기→어르신 폰 이전 불가, (b) 브라우저 데이터 정리 시 통째 소실. **구성 JSON을 base64url로 URL 프래그먼트(`#cfg=…`)에 직렬화한 공유 링크 + QR**이 해답 — 프래그먼트는 서버로 전송되지 않아 서버 무저장 원칙 유지.
- [ ] 설정 완료 시 복구 링크 자동 생성 → "부모님께 보내기 / 나에게 보관" (Web Share/링크 복사)
- [ ] 링크 열면 구성 미리보기 확인 1단계 후 localStorage 임포트 (딸이 원격에서 수정→재전송도 동일 메커니즘)
- [ ] PWA 설치 직후 `navigator.storage.persist()` 호출
- [ ] 인쇄용 QR 페이지(A4) — 재도달 경로를 종이로도

### 4. 온보딩을 LLM에 의존시키지 않는다 ("LLM은 향상이지 의존이 아니다" — 설계 제1원칙 계승)
질문 답변은 enum이므로 **정적 매핑 테이블(JSON)로 결정적으로 런처 생성**. LLM은 ⑦ 자유 입력 분류와 문구 품질에만.
- [ ] LLM 5초 타임아웃 → 규칙 결과 그대로 사용(사용자는 차이를 못 느낌)
- [ ] LLM 출력은 화이트리스트 앱 ID 배열만 허용, 패키지명·URL은 클라이언트 정적 테이블에서만 조립
- [ ] 서버 Gemma 호출에 `think:false` 고정 상수 + 파서에서 thinking 블록 방어적 제거 후 enum 검증 (★기존 프로젝트에서 문서화된 함정)

### 5. 접근성을 선언이 아닌 수치로 (Android판 §6 계승)
"rem 쓰면 시스템 글꼴 확대를 따라간다"는 통념은 **모바일에서 성립하지 않음** — 기본을 크게 + 앱 내 토글이 정답.
- [ ] 타일 라벨 24px+·본문 최소 20px, 전부 rem(데스크톱 심사위원 브라우저 설정 대응)
- [ ] 최상단 "글씨 크게/아주 크게" 토글 — root font-size 변수 하나로 전체 스케일, 설정값은 복구 링크에 포함
- [ ] 인터랙티브 요소 min 60×60px + 인접 간격 8px+, 텍스트 대비 7:1(비텍스트 3:1)
- [ ] 모든 타일 아이콘+텍스트 병기, aria-label, `:focus-visible` 스타일
- [ ] QA 기본 조건: 브라우저 글꼴 200% + 삼성 인터넷 '큰 글씨' 상태에서 전 화면 확인 (고정 height 금지 — min-height+패딩, 줄바꿈 허용)

### 6. PWA 홈 추가는 "보호자가 하는 단계"로 설계
- [ ] `beforeinstallprompt` 캡처 → "휴대폰 화면에 붙이기" 초대형 버튼
- [ ] 미발화 환경(삼성 인터넷 등)·iOS용 브라우저별 그림 가이드(⋮ 위치 화살표 지목)
- [ ] 보호자 체크리스트에 "아이콘을 홈 첫 화면 정중앙에 배치" 그림 안내
- [ ] 아이콘: maskable 최대 크기 + 고대비 단색 배경 + 큰 글자, 앱 이름 "온기" 2글자

### 7. 오프라인 앱 셸
인터넷이 끊기면 런처가 백지 → **전화 타일마저 못 쓰는** 사고. intent/tel 실행은 네트워크가 필요 없으므로 셸만 캐시하면 해결.
- [ ] Service Worker로 HTML/CSS/JS/아이콘 프리캐시 → 런처·타일 실행 완전 오프라인 동작
- [ ] 온라인 필요한 건 온보딩 AI뿐 — 오프라인이면 규칙 매핑으로 대체(P0-4와 결합)
- [ ] 에러는 원인별 쉬운 말 + 대형 재시도 버튼("인터넷이 잠시 안 돼요…")

### 8. PC 심사위원 데모 모드
심사위원(PC Chrome, 폰 없음)은 intent·tel·PWA 전부 무반응 → "죽은 사이트"로 보일 위험.
- [ ] 비모바일 UA 감지 → "체험하기" 버튼: 시드된 예시 런처(가상 어르신 구성 + 시드 탭 기록으로 추천 카드까지) 즉시 표시
- [ ] 타일 클릭 시 폰 프레임 목업 + "카카오톡이 열립니다" 토스트로 실동작 시뮬레이션
- [ ] 랜딩에 "휴대폰으로 체험하기" QR 상시 노출
- [ ] 데모 모드는 정적 데이터 — LLM 서버 상태와 무관하게 항상 동작

### 9. 롱프레스 전면 폐기 — 정리는 명시적 편집 모드로
손떨림 사용자에게 롱프레스는 오조작 폭탄이고 브라우저 컨텍스트 메뉴와 충돌.
- [ ] 숨김은 하단 "⚙ 타일 정리" 버튼 → 편집 모드(타일별 큰 숨기기/되살리기 토글) → "완료"로만
- [ ] 숨김 전 확인 1회 + 설정에 "숨긴 타일 되살리기" 목록
- [ ] 일반 모드 타일에 `-webkit-touch-callout:none` + user-select 차단

## P1 — 권장 (10건)

1. **"OO에게 전화" 별칭 타일**: 보호자 설정에서 자주 거는 사람 2~3명(이름+번호) → 최상단 대형 타일(`tel:번호` — 다이얼러에 번호 채움, 발신은 사용자 탭. Android판 ACTION_DIAL 오발신 방지 원칙과 일치). 복구 링크에 포함.
2. **자유 입력 되묻기**: 분류 결과 즉시 반영 금지 — "'OO'을 쇼핑·배달 칸에 넣을까요? [넣기]/[아니요]". 처리 중 "찾고 있어요…", 실패·타임아웃 시 14종 카테고리 대형 버튼 직접 제시. 오탈자 허용(자모 유사도 매칭).
3. **온보딩 흐름**: 첫 화면 [제가 쓸 거예요]/[부모님 폰에 설정해 드려요] 분기(문구 세트 전환) → 글자 크기 설정 선행 → 질문은 화면당 1개+진행 표시("3개 중 1번째")+모든 질문에 "안 써요/잘 몰라요" 선택지 → "건너뛰기" 시 기본 4타일(전화·카톡·카메라·사진) 즉시 생성.
4. **추천 카드 위치 고정**: 타일 그리드는 절대 자동 재배열 금지(공간 기억 보호). 추천은 상단 고정 슬롯 1개, 타일과 동일 디자인 + "이 시간에 자주 쓰셨어요" 라벨(광고 오인 방지 — 배너 이미지·애니메이션 금지).
5. **미설치 폴백 완충 페이지**: Play 스토어 직행 대신 자체 안내("앱이 설치되어 있지 않아요" + [보호자에게 전화] + [이 타일 숨기기]), 스토어 이동은 보조 버튼.
6. **프라이버시 문구 정합성**: "완전 온디바이스" 계열 표현 사용 금지(서버 AI 사용이므로 허위). 답변 전송 직전 큰글씨 고지("답하신 내용은 화면을 만드는 데만 쓰고 저장하지 않아요"), 서버 요청 본문 무로그, 탭 기록·추천은 전량 클라이언트 규칙(서버 전송 금지).
7. **복구 링크 보안**: 임포트 시 zod 스키마 검증(카테고리 enum·패키지 화이트리스트), 라벨은 텍스트 노드로만 렌더, tel:은 숫자 검증 + 060/1900 등 유료번호 차단 + 전화 타일에 번호 병기.
8. **뒤로가기**: 온보딩 단계마다 `pushState` — 하드웨어 뒤로가기 = 이전 질문. 답변은 단계별 즉시 저장(이어하기).
9. **라이트 고대비 단일 테마**: `color-scheme: light` 명시(삼성 인터넷 강제 다크모드의 임의 색변환 방어), 대비 7:1+ 여유 확보. 갤럭시 다크모드 ON QA 1회.
10. **용어 금지**: UI 문구에서 "PWA·런처·설치·배너" 금지 → "홈 화면에 붙이기", "앱 열기". 존댓말·쉬운 말.

## P2 — 향후/축소 (5건)

1. iOS: 검증된 스킴(tel:, 카카오톡 등)과 웹 폴백 있는 타일만 노출 + "아이폰은 일부 기능만 지원돼요" 배너.
2. 추천 콜드스타트: 카테고리 누적 탭 5회 미만이면 카드 숨김(또는 시간대 기본 카드). 심사 시연은 시드 기록 데모 모드로.
3. 제출 전 축소 사용자 테스트: 마지막 2시간, 실사용자 1명에게 삼성 실기기로 4과업(전화·카톡·사진·앱 찾기) + 보호자 시나리오.
4. 표현 주의: 지원서·소개에 "자동 스캔" 기재 금지 → "질문 기반 맞춤 구성"(허위 기재 방지).
5. 보호자·어르신 브라우저 상이 → 복구 링크 메커니즘으로 완화(설치 가이드에 "부모님 폰 기본 브라우저 그대로" 명시).

## 구현 순서에 미치는 영향

1. **0시간대**: 삼성 인터넷·Chrome 실기기 스모크(P0-1) — 여기 결과가 실행 계층 설계를 확정
2. 정적 매핑 온보딩 + 런처 + 접근성 토큰(P0-4·5) → 3. 복구 링크 + PWA + 오프라인 셸(P0-3·6·7) → 4. LLM 자유입력·데모 모드(P0-8) → 5. P1 문구·안전장치 → 6. 마지막 2시간 축소 사용자 테스트

## 지원서 초안에 미치는 영향

- 3-1(프로그램 설명): 음성 제거 + 런처 컨셉으로 재작성 시 "복구 링크로 보호자가 원격 설정" 포인트를 포함할 것 (차별화 요소).
- 3-4(활용 데이터)·3-5(차별성): "완전 온디바이스" 유사 표현이 들어가지 않도록 유지(현 초안은 "자체 GPU 서버 구동"이라 문제없음).
- 4-2(향후 계획): iOS 확대·스크린샷 인식은 향후 계획으로만.
