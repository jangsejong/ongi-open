## 1. 제품 정의

- **한 문장**: 설치된 앱을 온디바이스 AI가 생활 카테고리로 정리하고, 큰글씨와 음성으로 스마트폰을 쓰게 해 주는 **고령자·디지털 취약계층용 접근성 도우미**.
- **타깃 사용자**: 1차 = 국내 60대 이상 고령자(중저가 삼성 Android 비중 높음), 2차 = 저시력·운동기능 저하 사용자. 보조 이해관계자 = **보호자(가족)** — §8 온보딩에 개입 지점 정의.
- **핵심 가치**: ① **AI 추론 전량 온디바이스** — 요금·개인정보 걱정 없음(음성인식 경로는 §6 프라이버시 매트릭스 참조) ② 큰글씨·음성 우선 UI ③ "대신 해 주는" 것이 아니라 "스스로 하게" 만드는 자립 지원. **보호자 연동(v1.2)도 이 원칙을 따른다** — 보호자는 보고 말해 줄 뿐 조작은 어르신이 직접 한다(`50_guardian_coaching.md`).
- **설계 제1원칙 — LLM은 향상(enhancement)이지 의존(dependency)이 아니다**: 분류·음성 명령·런처의 기본 동작은 규칙 기반으로 성립하고, LLM은 그 위에서 품질을 높인다. 저사양 기기(경량 모드)에서도, 그리고 **모델 다운로드가 끝나기 전에도** 핵심 접근성 가치가 동작해야 한다.

## 4. 시스템 아키텍처

### 4.1 클라이언트 구조 (Flutter — 현행 `app/` 확장)

```
app/lib/
├── main.dart                 # FlutterGemma.initialize(LiteRtLmEngine) + 백그라운드 부트스트랩
├── app.dart                  # OngiDeps 의존성 조립 + 온보딩·역할 게이트
├── core/                     # config(카테고리·모델 상수)·theme(접근성 §6 스펙)·db(sqflite)
├── ai/                       # device_gate(RAM 게이팅·crash-flag)·llm_runtime(세션 재사용)·intent_router(2단계 캐스케이드)
├── native/                   # pigeon 생성 코드 — 단일 Kotlin 모듈의 5 API, 전부 @HostApi 단방향
│   ├── app_scan_api          #   앱 목록·아이콘·실행
│   ├── usage_stats_api       #   권한 상태·이벤트 세션 조회
│   ├── intent_actions_api    #   앱 실행·삭제 안내·tel/sms/카메라 표준 인텐트
│   ├── device_stats_api      #   RAM·저장공간·Wi-Fi·알림 권한 요청
│   └── coaching_api          #   화면 공유 FGS 수명·포그라운드 앱 조회 (v1.2)
└── features/                 # launcher · apps · model · voice · routine · cleaner · settings
                              # · onboarding · spike · coaching(v1.2, 대회 범위 밖)
```

> 설계 당시 예정했던 **설치/제거 이벤트 push(`@FlutterApi`)는 만들지 않았다** — 앱 목록은 화면 진입 시
> 조회로 충분했고, 양방향 콜백을 열지 않는 편이 ADR-16(쓰기 경로 0)과도 일관된다.

- **네이티브 브리지는 처음부터 pigeon 단일 모듈**: MethodChannel 수동 직렬화 대신 타입세이프 코드 생성(공식 권장). 채택 근거는 구조화 모델이 많다는 것과 양방향 이벤트(설치/제거 push)를 쓸 수 있다는 것이었는데, 후자는 위 주석대로 결국 만들지 않았다 — 실제 이득은 타입세이프 코드 생성 쪽이다.
- ⚠️ **`installed_apps` 패키지 사용 금지**: 라이브러리 매니페스트가 `QUERY_ALL_PACKAGES`·`REQUEST_DELETE_PACKAGES`를 직접 선언해 **매니페스트 머지로 앱에 자동 주입**된다(§5 방침과 정면 충돌 — 리스크 #6의 실제 사례). `device_apps`는 discontinued. 앱 스캔은 pigeon 자체 모듈로만.

### 4.2 AI 파이프라인 (핵심 설계)

**음성 명령 — 2단계 캐스케이드**:

```
푸시투토크 버튼 → 플랫폼 STT(partial=화면 자막용만, final만 입력)
  → [1차] 규칙 매칭 (수십 ms): 앱 이름·별칭·초성 사전 + 표준 기능 매핑(전화/문자/카메라…)
  → [2차] 매칭 실패·다의성 시에만 Gemma 4 E2B: 액션 ID + 인자 JSON 선택 (함수호출 스타일)
  → 네이티브에서 화이트리스트 검증 후 인텐트 조립·실행 → TTS + 큰글씨 피드백
```

- **LLM은 액션 ID를 고를 뿐, 인텐트 문자열을 만들지 않는다** — 프롬프트 인젝션·오동작 차단.
- LLM 처리 중(수 초) "찾고 있어요" 음성+로딩 표시, 타임아웃 시 후보 2~3개를 큰 버튼으로 제시(터치 마무리).
- **비가역 행동(삭제·발신)은 음성만으로 실행 금지** — 음성+터치 이중 확인. 전화는 기본 ACTION_DIAL(다이얼러 표시, 무권한)로 오발신 방지 — ACTION_CALL(즉시 발신, 위험 권한)은 채택하지 않음.

**앱 분류**: 설치 시 배치 처리 — 카테고리 사전(패키지명·스토어 카테고리 힌트) 우선, 모호한 것만 LLM 보정. 결과는 sqflite 캐시(매 실행 재분류 금지). **배치 분류는 WorkManager 제약(충전 중 또는 유휴 시)으로 실행** — CPU 백엔드 기기의 발열·배터리 소모 방지(W1에서 일괄 분류 소요시간·발열 실측).

**루틴 추천**: 사용 세션 → hour-of-day × day-of-week 히트맵 → 규칙으로 후보 생성 → **LLM은 안내 문구 생성만** 담당.

### 4.3 LLM 운영 — 모델 수명주기

**모델**: `litert-community/gemma-4-E2B-it-litert-lm` / 파일 `gemma-4-E2B-it.litertlm` / **2,588,147,712 bytes(약 2.6GB)** / Apache 2.0 / 게이트 없음·토큰 불필요. S26 Ultra 실측: CPU decode 46.9 tok/s(RSS 1.7GB), GPU 52.1 tok/s. **E4B는 배제**(3.66GB, CPU 메모리 3.3GB, 속도 1/3 — 타깃 기기와 불일치). ※ 벤치 기기는 최상위 플래그십 — 중저가 기기 실속도는 W1 실측으로 확정.

**RAM 게이팅** (온보딩 1회, `device_info_plus` physicalRamSize/isLowRamDevice):

| 기기 RAM | 모드 |
|---|---|
| <4GB 또는 isLowRamDevice | **경량 모드**: LLM 미탑재. 규칙 기반 분류+명령 사전 매칭+런처 (핵심 가치 유지) |
| 4~6GB | E2B **CPU** 백엔드, maxTokens 1024 |
| ≥6GB | E2B **GPU** 시도 → 실패 시 CPU 강등 |

**GPU 안전장치**: GPU 초기화 실패가 Dart 예외가 아니라 **프로세스 crash/프리즈로 나타난다**(flutter_gemma #351 Xclipse 940 — open, #324 Mali WebGPU 프리즈 — closed·1.0.0 시절 회귀로 1.2.x 재현 여부 W1 확인). → ① AndroidManifest에 OpenCL `uses-native-library` 4종(libOpenCL, libvndksupport 등) 선언 ② 초기화 직전 crash-flag 영속 기록 → 재실행 시 플래그 잔존이면 CPU 강등 ③ CPU도 실패하면 경량 모드.

**다운로드 (1순위 리스크 — 조건부 함정)**:
- flutter_gemma 문서는 Android 다운로드에 **9분 타임아웃**이 있다고 주장하나, 상류 background_downloader의 코드·문서는 **foreground 모드에서는 9분 제한이 적용되지 않는다**고 명시 — 상충한다. 즉 "타임아웃 → 0바이트 재시작 루프"는 무조건적 사실이 아니라 **(a) POST_NOTIFICATIONS 거부 → background 폴백 시, (b) flutter_gemma가 foreground 설정을 상류에 제대로 전달하지 못하는 경우의 조건부 리스크**다. → **W1 스파이크에서 실측 확정**(foreground+알림 허용 상태로 9분 초과 다운로드 지속 여부).
- 타임아웃이 적용되는 경로라면 성공 조건은 **지속 약 40Mbps(4.8MB/s) 이상**(2.6GB÷540초) — 사전 속도 추정 임계값은 이 수치 기준.
- 이어받기: flutter_gemma가 HF를 resume 불가로 취급한다(구현 제약 — **CDN 자체는 강한 ETag + Range 지원 실측**). 따라서 차선책으로 **자체 다운로드 로직(Range 이어받기) 구현** 카드가 유효하다.
- 트랙 A(대회): HF 직링크 + 사전 체크(Wi-Fi 여부·가용 저장공간 **3.6GB 이상**·속도 추정). 트랙 B(스토어): **자체 CDN**(R2 계열 — egress 무료) 재호스팅, Apache 2.0 4조에 따라 적법(LICENSE 사본·출처 고지 유지). 차선책 = Play for On-device AI(베타·Flutter 브리지 없음 — 채택 보류).
- 구현 필수 선언: `foreground: true` + Android 14+ `FOREGROUND_SERVICE_DATA_SYNC` 권한 + dataSync 서비스 override + `POST_NOTIFICATIONS` 런타임 권한(거부 시 background 폴백 → 9분 제한 노출 가능 — 거부 상태에서는 다운로드 화면을 열어둔 채 진행하도록 안내).
- 완료 검증: `isModelInstalled`만 믿지 말 것(#84 부분 다운로드 오탐 이력) — **파일 크기(2,588,147,712B) + sha256 대조**(기대 해시 앱 상수 내장. CDN 재호스팅 시 원본 HF 해시와 일치 확인).

**추론 운영**: 세션(채팅)은 앱 수명 동안 1개 생성·재사용 — 세션 생성·프리필이 메인 isolate 동기 FFI라 호출마다 UI 프리즈(#364, open). 응답은 스트리밍으로 첫 토큰 우선 표시. thinking 출력은 `ModelType.gemma4` + thinking 필터로 제거. 장시간 사용 시 네이티브 메모리 미반환 누수(#348, open) — QA 재현 테스트 + 필요 시 주기적 엔진 재생성 정책.

- **개인 데이터의 "외부 전송 0"은 유지된다.** 코칭을 켜도 나가는 것은 **어르신이 직접 연 세션 중의 화면 프레임뿐**이고(P2P), 저장 0·상시 수집 0이다(`50_guardian_coaching.md` §1). 릴레이는 요청 전달과 시그널링만 하며 어르신 데이터를 보관하지 않는다.
  ⚠️ 다만 **"네트워크 접속 0"은 아니다.** 프라이버시 문구를 쓸 때 "데이터를 보내지 않는다"·"자체 서버가 없다"·"아무 데도 접속하지 않는다"를 **각각 다른 주장으로 구분할 것.** 실제로 남아 있는 것은 둘이다.
  - **모델 다운로드(최초 1회)** — `core/config.dart`의 `modelUrl`이 하드코딩 상수이고 Hugging Face로 나간다. 이것이 **앱이 스스로 여는 유일한 외부 연결**이며, 끝나면 서버 의존이 사라진다. "외부 연결이 없다"고 쓰면 이 줄과 정면으로 모순된다(v0.0.28에서 보고서 문구를 이 범위로 좁혔다).
  - **음성인식** — OS 음성 서비스를 거치므로 기기·사용자 설정에 따라 제조사 서버를 탈 수 있다(§6 매트릭스·ADR-14). 앱은 어느 쪽도 강제하지 않는다 → "전 기능 오프라인" 주장 금지.
  - 코칭 **릴레이는 여기에 해당하지 않는다** — v0.0.25에서 기본 주소 상수를 없앴고, 사용자가 설정에 직접 넣기 전에는 접속도 재시도도 하지 않는다(`app/test/relay_address_test.dart`가 고정). 근거·남은 개선안은 루트 `README.md`의 "릴레이 접속" 절.

## 6. 음성 UX · 접근성 스펙

### 음성 원칙 (리서치 근거)

- **푸시투토크 확정, 웨이크워드 포기**: speech_to_text는 상시 청취 미지원(공식), iOS 세션 1분 하드 리밋, Android 무음 1~3초 시스템 컷오프(pauseFor로 연장 불가). 런처 하단 초대형 마이크 버튼 1개.
- 안내 문구는 "천천히 말씀하세요"가 아니라 **"짧게 말씀하세요"** — 느린 발화는 Android 무음 컷오프에 걸려 문장이 반토막 난다.
- **에코+되묻기 기본**: 인식 결과를 큰글씨+음성으로 반복("카카오톡을 열까요?") 후 실행. partial 결과는 자막 표시 전용.
- TTS: `setSpeechRate` 표준값이 **Android=1.0, iOS=0.5로 다름** — 플랫폼별 상수 분리(시작점 Android 0.7~0.8 / iOS 0.4~0.45) + 설정에 "말 빠르기" 슬라이더. `awaitSpeakCompletion(true)`로 TTS 종료 후 STT 시작(자기 음성 재인식 방지).
- **TalkBack/VoiceOver 공존**: `MediaQuery.accessibleNavigation` 감지 시 자체 TTS 프롬프트 억제(이중 발화 충돌 방지 — Android 공식 지침), 모든 위젯에 Semantics 라벨 완비.
- STT 초기화 실패(구글 음성서비스 부재 기기)·인식 실패 폴백: 텍스트 입력·버튼 경로 상시 제공.
- listen 파라미터: listenFor 15~30s, pauseFor 4~6s(Android 미적용 전제), partialResults true, localeId 'ko_KR'.

```
     - 다운로드 중에도 런처·음성(규칙 매칭)은 정상 동작
[4] 사용통계 권한: 가치 체감 후(예: 첫날 저녁 루틴 카드 예고와 함께) 전체화면 고지 → 설정 딥링크
[5] 마이크 권한: 음성 버튼 첫 탭 시
```

**보호자 개입 지점 (1차 범위 — ADR-12)**: ① 초기 설정 대행(온보딩 전 과정을 보호자가 진행하는 것을 전제로 문구 설계) ② 자주 쓰는 연락처·앱 별칭 등록("큰딸" → 연락처 매핑) ③ 문제 발생 시 "문제 알리기" 화면의 진단 로그를 보호자가 메신저로 공유(수동 opt-in — §9 관측성). 원격 관리·모니터링은 범위 외(프라이버시 원칙과 충돌).

**④ 보호자 통화 코칭 (v1.2 — 대회 범위 밖, 상세 = [50_guardian_coaching.md](50_guardian_coaching.md))**: 어르신이 홈의 "도와주세요" 버튼 1탭으로 세션을 열면 사전 등록·승인된 보호자와 통화가 연결되고, 보호자는 어르신 화면을 보며 단계적으로 알려 준다. **보호자가 얻는 능력은 보는 것과 말하는 것뿐이고 화면 조작은 어르신이 직접 한다** — 기기로 들어오는 명령 채널을 만들지 않으므로(ADR-16) 위 ③의 "원격 관리·모니터링 범위 외" 원칙과 충돌하지 않는다. **본인인증은 세션 진입 조건이 아니라 코칭받는 첫 과업이다**(ADR-17) — 본인인증조차 어려운 사람이 주 타깃이기 때문이다. 세션 개시 권한은 어르신에게만 있고 보호자·서버·관리자는 세션을 열 수 없다.

## 9. 테스트 · 운영

### 테스트 전략

- **실기기 매트릭스 (RAM 게이팅 3등급 각 1대 이상)**: 예 — Galaxy A16(4GB)=경량 모드, Galaxy A35(6GB)=CPU, Galaxy S23+(8GB)=GPU. W1에서 확보·확정.
- **CI (GitHub Actions)**: `flutter analyze` + `flutter test` + **merged manifest에 금지 권한 부재 검사**(QUERY_ALL_PACKAGES·BIND_ACCESSIBILITY_SERVICE·BIND_DEVICE_ADMIN·RECEIVE_BOOT_COMPLETED·BLUETOOTH) + `pytest server/test_relay.py` + ruff.
  ⚠️ **아직 구성하지 않았다** — `.github/`가 없고 위 검사는 전부 수동이다. Public 전환(§10 M4) 때 함께 세운다.
- **자동화 테스트**: core(분류 규칙·별칭 매칭·루틴 집계)와 ai(캐스케이드 라우팅 — LLM은 fake 주입) 단위 테스트 중심. LLM 실호출 테스트 금지(워크스페이스 규약).
- **고령 사용자 테스트 프로토콜 (M3 게이트)**: 참가자 3~5명(60대+), 핵심 과업 5개(전화 걸기·카카오톡 열기·사진 보기·앱 찾기·음성 명령), 성공률·소요시간·개입 횟수 기록. 통과 기준: 도움 없이 과업 성공률 80%+.
- **QA 특별 항목**: #348 메모리 누수 재현(연속 추론 100회 RSS 추적), GPU crash-flag 시나리오, fontScale 1.3 레이아웃, TalkBack 동시 사용.

### 운영 (버전·업데이트·관측성)

- **버전 정책**: semver. 앱 버전 ↔ 모델 파일 호환은 **모델 매니페스트**(파일명·크기·sha256 표)로 관리 — 불일치 시에만 재다운로드를 고지하고, "급하지 않음 — Wi-Fi에서 나중에" 기본 선택지 제공(엔진 업데이트로 인한 2.6GB 재다운로드가 고령자 최악의 업데이트 경험이 되지 않게).
- **크래시 리포팅 (ADR-13)**: 트랙 A = 로컬 진단 로그 + 설정 내 "문제 알리기" 화면(로그 파일 수동 공유 — 보호자 경유, opt-in). 트랙 B = Play Vitals(기본 제공) + opt-in 크래시 리포터 도입 여부는 프라이버시 문구와 함께 별도 결정. **자동 원격 수집은 하지 않는다**("기기 밖 전송 없음" 약속 유지).

| 21 | 보호자 연락처 **사전 특정 + 등록 변경은 어르신 본인 확인 필수**. 세션 신뢰 앵커는 전화번호가 아니라 **등록 앱 인스턴스** | 사칭 피싱범이 이 기능을 발판으로 삼는 경로를 구조로 차단 — **온기가 새 피싱 채널이 되지 않는다.** 등록 변경은 지속적 자격 부여 = 실제 권한 위임이므로 ADR-17 기준(권한 있는 곳에만 게이트)상 인증이 정당. 발신번호 거짓표시가 실재하므로(전기통신사업법 제84조의2 금지·제95조의2 처벌, 변작기 규제 강화가 방증) 번호를 신뢰 근거로 쓰지 않는다 |
