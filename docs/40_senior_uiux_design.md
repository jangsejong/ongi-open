> 작성: 2026-07-14. **상태: 기획·설계 시작(초안)** — 화면별 점검 항목은 코드/실기기 확인 후 확정한다.

## 1. 목적과 범위

온기의 대상 사용자(디지털 취약계층·고령자)에 맞춰, 공인 리서치 근거를 바탕으로 화면·문구·인터랙션을 점검하고 개선 백로그를 정의한다.

- **범위**: Android 앱(M1~M3 구현분) — 온보딩·모델 다운로드, 카테고리 런처, 음성 명령, 루틴 추천, 미사용 앱 정리, 설정. **+ v1.2 보호자 통화 코칭**(§4.7 — 코드는 v0.0.20에 구현됐고 **실사용자 점검이 아직**이라 항목이 ☐로 남아 있다).
- **비범위**: 아키텍처·LLM 운영 정책(→ 10_product_design.md), 보고서·대회 산출물.

## 3. 온기 UI/UX 설계 원칙 10 (근거 코드)

1. **버튼은 버튼처럼** — 텍스트 링크·화살표(>)만으로 진입점을 만들지 않는다. 명확한 버튼 형태 + 외곽 경계. *(toss①, GC1, DB1)*
2. **아이콘+텍스트 병기** — 아이콘 단독 사용 금지, 동일 기능은 전 화면 동일 아이콘. *(GC1, 3-2 구성)*
3. **터치 타깃 ≥48dp, 간격 ≥8dp** — 싱글 탭만으로 모든 조작 가능(더블탭·드래그·롤오버 금지). 슬라이더에는 ±스텝 버튼 병행. *(GA4, CB2, 3-2 조작)*
4. **한 화면 = 한 가지 일** — 정보량 최소화, 깊이 3단계 이내의 넓고 얕은 구조. 스크롤보다 페이지 방식 우선, 스크롤이 필요하면 하단 콘텐츠가 잘려 보이게 해 스크롤 가능성을 드러낸다. *(IC1, DA1, CF3, 3-6, toss⑤)*
5. **행동형 레이블, 단언적 문장** — 질문형("어떤 서류가 필요한가요?")·비유·전문용어 금지, "필요한 서류 확인하기"식 동사형. *(toss④, DC1, 3-5, 3-8)*
6. **진행 상태를 항상 보여준다** — 현재/전체 단계, 달성도, 다음에 일어날 일을 예고. *(DG1, DD1, 3-8 상태)*
7. **시간 압박 금지** — 제한시간·자동 넘김·자동 스크롤 없음. 불가피한 타임아웃은 여유 있게 + 재시도 안내. *(CB1, IA4, 3-8 시간)*
8. **고대비 + 색 비의존** — 텍스트 대비 4.5:1 이상, 흑백에서도 정보 식별 가능, 황/청·적/녹 조합 회피. *(GB1·GB2, GD1, 체크리스트-색상)*
9. **오류는 원인+해결책으로** — 실패 화면엔 원인별 안내와 다음 행동 버튼. 선택 불가 항목은 미리 비활성화. *(CG1·CG2)*
10. **낮춰 보지 않는다** — '시니어 모드'·'이지 모드'류 명명·문구 금지, 과도하게 유치한 색·3×3 왕대형 아이콘 지양. 익숙한 제스처(스와이프 등)는 허용. *(3-5 감성, 3-2 모바일, 3-7 인터랙션)*

## 4. 화면별 점검·설계 방향 (초안)

각 항목의 "현행"은 README/설계문서 기준이며, ☐ 항목은 코드·실기기 확인이 필요하다.

### 4.1 카테고리 런처 (features/launcher)

- 현행: 큰글씨 카테고리 타일(14종), 본문 22sp 접근성 테마, 루틴 추천 카드, 상태 배너.
- ✅ **카테고리 14종 vs 그리드 권장 3×4(최대 12)** *(3-2 모바일, CF3, toss⑤)* — v0.0.16에서 **페이지 방식(2×3 고정 6칸 × 3쪽, 이전/다음 큰 버튼 + 쪽 표시)** 적용. 스크롤 제거로 하단 미발견 문제 해소, 끝 쪽 버튼 비활성(CG2).
- ✅ 앱바 아이콘 단독 버튼 3개 → '설정' 텍스트 병기 1개로 정리, W1 스파이크 버튼 제거, 앱 정리는 설정 화면 이관 *(GC1·IC1, v0.0.16)*.
- ✅ 카테고리 타일 아이콘+텍스트 병기 — 점검 결과 충족(아이콘 44 + 30sp 라벨). *(GC1)*
- ☐ 루틴 추천 카드가 "예시/추천"임이 명확한지 — 사용자가 자기 데이터로 오인하지 않게. *(toss②)*
- ☐ 중요 기능(음성 버튼)이 다른 요소보다 2~3배 강조되는지. *(3-2 주요 아이콘 강조)*
- ✅ 앱 목록 행의 '>' 화살표 → '바꾸기' 버튼 교체(싱글 탭 편집 경로, 길게 누르기는 보조) *(toss①·CB2, v0.0.16)*.

### 4.2 음성 명령 (features/voice)

- 현행: 하단 초대형 푸시투토크, partial 자막, 에코+되묻기 큰버튼, TTS 0.75배속, 미인식 시 자동 재청취 1회.
- 강점: CC2(음성 인터랙션)·폴백 체계(음성은 LLM 없이 성립)는 가이드라인 방향과 일치.
- ☐ "듣고 있어요" 등 상태 문구가 다음 행동을 예고하는지("말씀이 끝나면 자동으로 알아들어요"). *(DD1)*
- ☐ 되묻기 화면의 두 버튼(실행/다시)이 좌부정·우긍정 관례를 따르는지. *(3-3 관습)*
- ☐ 실패 시 원인+해결 안내("주변이 시끄러우면 잘 안 들려요. 버튼을 누르고 다시 말씀해 주세요"). *(CG1)*
- 청각 피드백 외 시각·진동 병행 여부 검토. *(DD2)*

### 4.3 온보딩·모델 다운로드 (features/onboarding, features/model)

- 현행: 환영 화면 → 동의(2.6GB·Wi-Fi 경고·저장공간 체크) → 진행률·검증 → 원인별 실패 안내.
- 강점: step-by-step + 원인별 오류 안내는 DG1·CG1 부합.
- ☐ 안내 문구에 질문형·전문용어(모델, 다운로드 검증 등)가 없는지 — "인공지능 준비하기"식 자연어로. *(toss④, DC1, IA1)*
- ☐ 진행률 화면에 남은 시간/단계가 표시되는지, 중간 이탈 후 재진입 시 이어받기가 안내되는지. *(3-8 상태)*
- 온보딩에 예시 이미지·모션을 쓰게 될 경우: '예시' 표기를 크게, 개인화 텍스트(이름 등) 사용 금지, 따라 해야 할 행동은 문구로 명시. *(toss②③)*

### 4.4 루틴 추천·미사용 앱 정리 (features/routine, cleanup)

- 현행: 시간대 습관 기반 추천 카드(LLM 문구), 학습 중 안내 카드, 30일 미사용 목록 → 이중 확인 → 시스템 삭제 다이얼로그.
- 강점: 이중 확인 + 시스템 다이얼로그는 CG2(오류방지) 부합.
- ☐ 추천 문구가 단언적·행동형인지("지금 유튜브 볼 시간이에요" → 탭하면 무슨 일이 생기는지 명확한지). *(3-8 단언적 용어)*
- ☐ 정리 목록에서 삭제 불가 앱(시스템 앱)이 미리 제외/비활성화되는지. *(CG2)*
- ☐ "30일 미사용" 같은 기준이 사용자 언어로 설명되는지("한 달 동안 안 쓴 앱이에요"). *(DC2)*

### 4.5 설정 (features/settings)

- 현행: 말 빠르기 확대 슬라이더(64dp) + 천천히/빠르게 스텝 버튼, 즉시 적용+미리듣기 — CB2·CF2 부합(슬라이더+스텝 버튼 패턴은 3-2 '아이콘 조작' 권장과 일치). 그 아래 보호자 정하기 진입, **이 휴대폰 역할**(어르신↔보호자 전환, 확인 다이얼로그 경유), 앱 정리, 인공지능 상태·복구.
- **[점검 ☐] 역할 전환 문구가 어르신 언어인지** — 현행 "도와주는 쪽으로 바꾸기"/"이 휴대폰을 직접 쓰시나요?". 잘못 눌렀을 때 되돌아오는 길(보호자 홈 상단 "내가 쓸래요")이 발견 가능한지 실사용자로 확인이 필요하다. *(DC1, CG1, GD1 원래대로 복귀)*
- **[백로그] 글자 크기 조절** — 가이드라인 체크리스트 필수 항목(5단계 이내 + 원래대로 복귀). 현행 고정 22sp → 3단계(기본/크게/아주 크게) 검토. *(GD1, 체크리스트-타이포)*
- **[백로그] 고대비/흑백 모드** — 색 비의존 검증 겸용. *(GB1)*

### 4.6 공통 (core/theme, 문구 전반)

- ✅ Android 15+ edge-to-edge 하단 겹침 — 런처·카테고리 목록·앱 정리에 SafeArea(top:false). '말로 하기'가 3버튼 내비 바에 가리던 문제 *(기기 호환성 점검, v0.0.17)*.
- ✅ 세로(portrait) 고정 — 가로 회전 시 격자·비스크롤 화면 깨짐 방지 *(v0.0.17)*.
- ✅ 경량 모드 갇힘 복구 — 설정 '인공지능' 섹션(상태 + 다시 켜보기), isLowRamDevice 오판 수정 *(v0.0.17)*.
- ☐ 글꼴 배율 1.5~2.0× 중첩 시 비스크롤 화면(모델 동의·환영·음성 확인·사용통계 고지) 넘침 여부 — 실기기 확인 후 필요 시 SingleChildScrollView/FittedBox 보강.

- ☐ 전 화면 텍스트 대비 4.5:1 이상(자동 검사: flutter test 또는 수동 대조). *(GD1)*
- ☐ 문구 전수 점검: 질문형 → 행동형 치환, 전문용어(캐시, 동기화, 모델 등) → 생활어. *(toss④, DC1)* — `grep`으로 UI 문자열 추출 후 일괄 리뷰.
- ☐ 행간: 본문 TextStyle height 1.6~1.8 적용 여부. *(3-4 행간)*
- ☐ TalkBack 라벨(Semantics) 전 인터랙티브 요소 부여 여부. *(DC3)*

### 4.7 보호자 통화 코칭 (v1.2 — 구현됨, 시니어 관점 점검 미완)

- 현행: **코드는 v0.0.20에 구현됐다**(`app/lib/features/coaching/` — 도움요청·세션·화면 공유·보호자 등록 화면). 설계 = `docs/50_guardian_coaching.md`(ADR-15~21), 수치 스펙 = 같은 문서 §12.
  아래 ☐는 **화면이 없어서가 아니라 실제 화면을 시니어 기준으로 대조하지 않아서** 남아 있다. 대회 출품 범위 밖이라 우선순위가 뒤로 밀렸다(§5 백로그 5순위).
- 이 기능은 설계 원칙 10번(**낮춰 보지 않는다**)과 정면으로 맞물린다 — 보호자가 대신 해 주는 것이 아니라 **어르신이 직접 하도록 알려 주는** 구조이므로, 문구도 "대신 해 드려요"가 아니라 "같이 해 봐요"여야 한다. *(3-5 감성, 10_ §1 핵심 가치 ③)*
- ☐ **"도와주세요" 버튼**이 마이크 버튼("말로 하기")과 혼동되지 않는지 — 두 개의 초대형 버튼이 홈에 동시에 놓인다. 색·아이콘·라벨을 명확히 분리하고, 아이콘 단독 금지. *(GC1, 3-2 주요 아이콘 강조, toss①)*
- ☐ **화면 공유 요청 화면 문구에 전문용어가 없는지** — "화면 공유", "MediaProjection", "세션" 금지 → "지금 보고 계신 화면을 ○○○님이 볼 수 있게 해요"식 생활어. *(toss④, DC1, IA1)*
- ☐ 같은 화면이 **"누가 · 무엇을 볼 수 있는지 · 언제 끝나는지" 3항목을 예고**하는지. 어르신이 무엇에 동의하는지 모르고 누르는 상황을 만들지 않는다. *(DD1, DG1)*
- ☐ **취소가 기본 포커스이고 동일 크기**인지, 좌부정·우긍정 관례를 따르는지. *(3-3 관습, CG2)*
- ☐ **카운트다운·자동 승인이 없는지** — 원칙 7(시간 압박 금지)이자 Play 동의 규정 요건. 대기 화면에도 "천천히 하세요" 톤 유지. *(CB1, IA4, 3-8 시간)*
- ☐ **공유 중 배너의 "가리기"·"끝내기"가 상시 발견되는지** — 진행 상태를 항상 보여주는 원칙 6의 적용. 60dp+ · 대비 7:1 · 스크롤해도 사라지지 않게. *(DG1, GB1, GD1, GA4)*
- ☐ **민감 화면 자동 가리기 시 안내가 원인+해결 형태**인지 — "가려졌습니다"로 끝내지 말고 "돈 보내는 화면은 보여드리지 않아요. 이 일은 통화를 끊고 하세요"까지. *(CG1, DC2)*
- ☐ **종료 후 요약·되돌리기**가 사용자 언어인지 — "세션 종료", "롤백" 금지 → "○○○님이 도와주신 내용", "원래대로 하기". *(DC1·DC2, GD1 원래대로 복귀)*
- ☐ **보호자 등록·연락처 변경 화면**(사전 A/A′)의 본인 확인 단계가 어르신에게 도달 가능한지 — 지문·잠금 자격증명이 없는 어르신은 기능 자체가 비활성되므로, 그 안내가 막다른 길이 아니라 **다음 행동**을 제시해야 한다("휴대폰 잠금을 먼저 설정해 주세요" + 설정 딥링크). *(CG1·CG2)*
- ☐ **보호자 홈의 "연결 서버 설정"·미설정 경고**(v0.0.28 신설) — 접힘 위젯 안의 URL 입력은 이 문서 기준으로는 어려운 요소다. 보호자 모드는 ADR-20으로 시니어 제약이 면제되지만, 배우자 보호자(아래 항목)에게는 그대로 노출된다. 경고 카드가 원인+해결 형태인지("요청을 받을 수 없습니다" + "위 '연결 서버 설정'에 주소를 넣어 주세요")와, 이 설정을 가족이 대신 넣는 경로가 안내되는지 점검. *(CG1, DC2, DG1)*
- ☐ **보호자 모드는 이 문서의 시니어 제약 대상이 아니다**(ADR-20 — 22sp·60dp·7:1 면제). 다만 보호자가 60대 이상인 경우(배우자 보호자)가 실제로 존재하므로 **보호자 모드에도 큰글씨 토글**을 둘지 검토. *(GD1)*
- ☐ 전 신규 화면 TalkBack 라벨(Semantics) 부여. *(DC3)*

> **UT 우선 항목**: `50_` §12의 통과 기준 중 "**보호자 통화 안내 하에** 화면 공유 동의 성공률 100%"는 이 문서의 §5 4단계(시니어 UT)에서 검증한다. 어르신 혼자서는 OS 동의 다이얼로그를 통과하지 못한다는 것이 설계 전제이므로, **혼자 성공률이 아니라 안내받은 성공률을 재는 것**이 맞다.
