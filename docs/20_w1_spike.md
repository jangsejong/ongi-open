# W1 스파이크 — 실기기 측정 가이드

> 기획설계서 §11의 미결 항목을 확정하는 측정 절차. 앱 안에 계측 화면이 내장되어 있어
> **버튼을 순서대로 누르고 결과 JSON을 복사**하면 된다. 측정 후 결과를 이 파일 하단에 기록.

## 준비

0. ★**사전 게이트(로컬)** — "빈 계측 APK"(v0.0.32 사건)·"트리셰이킹 제외"(v0.0.34 사건) 두 실패 모드의 영구 가드. 셋 다 통과 전에는 세션·크레딧을 쓰지 않는다:

   ```bash
   sha256sum dist/ongi-w1-spike-v0.0.34.apk        # 37c3f9db… 대조
   # 계측 코드 포함 확인 — 'SPIKE 포함'이 아니면 플래그 누락 빌드(🧪 없음)
   python3 -c "import zipfile;so=zipfile.ZipFile('dist/ongi-w1-spike-v0.0.34.apk').read('lib/arm64-v8a/libapp.so');print('SPIKE 포함' if b'pluginLowMemoryNow' in so else '★SPIKE 플래그 누락 빌드')"
   ```

   설치 직후: `adb shell dumpsys package kr.tsp.ongi | grep -E "versionCode|versionName"` → 0.0.34 / 34

   8단계 시작 전: `adb shell df -h /data` → **가용 5GB 미만이면 착수 금지**(요구 가용 ≈3.6GB + 여유. 스파이크 다운로드는 `hasEnoughStorage()` 사전 체크 없이 직행이라, 공간 부족 중단이 540초 부근에 나면 9분 타임아웃 판정과 섞인다). **측정한 df 값은 세션 노트에 기록**해 실패 시 원인을 분리한다.

1. APK: `dist/ongi-w1-spike-v0.0.34.apk` (arm64-v8a 전용, 138.2MB, sha256 앞자리 37c3f9dbe1b207cb — `dist/`는 비커밋, 아래 재빌드 명령으로 생성)
   - Windows 탐색기(WSL 빌드 시): `\\wsl$\<배포판>\<저장소 경로>\dist\`
   - 전송: 카카오톡 나에게 보내기 / USB / `adb install ongi-w1-spike-v0.0.34.apk`
   - 설치 시 "출처를 알 수 없는 앱" 허용 필요. 재빌드: `cd app && flutter build apk --release --target-platform android-arm64 --dart-define=SPIKE=true`
   - ★**`--dart-define=SPIKE=true` 없이 빌드하면 🧪 계측 진입 자체가 빌드에서 빠진다**(v0.0.34 게이트 — 데모/제출 빌드에서 계측 화면을 제외하기 위함)
2. 권장 측정 기기: RAM 등급별 3대 (예: 4GB Galaxy A16 / 6GB A35 / 8GB+ S23 이상)
   — 1대만 있어도 해당 등급 결과는 유효
3. Wi-Fi 연결 상태에서 시작 (모델 2.6GB 다운로드)

> ★**제출(8/27 18:00) 전 최소 목표** — 상위 S시리즈 **1대·1세션**에서 **8→9→10 완주**(2.6GB 다운로드 → sha256 일치 → 로드 → 추론 tok/s). "전량 온디바이스 추론"의 유일한 실기기 실증이다. 임계 조정·벤더 비교(#324)는 제출 후 과제(Exynos 기기면 보너스로 딸려온다). RTL은 세션 종료 시 기기가 초기화되므로 8·9·10은 반드시 한 세션 안에서 연속으로.

### 주의

- (v0.0.34 APK~) 결과 JSON의 `isLowRamDevice`는 **네이티브 고정 속성**(판단 근거)이고 `pluginLowMemoryNow`는 순간 압박 참고값이다 — 키 구성이 다른 구버전 APK(v0.0.6 등) 결과와 섞지 말 것.
- **10번 벤치는 임계 조정 근거가 아니다** — 컨텍스트 1024·백엔드 미지정으로 돌아 프로덕션 구성(`OngiConfig.maxTokens` 2048·게이트 산출 티어)과 다르다. tok/s·PSS는 **온디바이스 추론 성립 증빙·기기 간 상대 비교용**으로만 쓴다.
- ★**10번 벤치에서 죽어도 crash 플래그는 남지 않는다** — 플래그는 프로덕션 경로(`LlmRuntime._doEnsureReady`: 로드 직전 기록, 성공·포착된 예외 시 삭제 → **로드 중 프로세스 사망 시에만 잔존**)에서만 기록되고, 스파이크 벤치는 `FlutterGemma`를 직접 호출해 그 경로를 타지 않는다. 재실행 후 기기 정보의 `false/false`를 "GPU 크래시 아님"으로 읽지 말 것.
- 프리즈·강제 종료의 **1차 증거는 logcat**(OpenCL/GPU 드라이버 라인)이다 — 벤치는 백엔드 미지정이라 JSON만으로는 GPU 귀속이 안 된다. 플래그·`tier` 강등을 증거로 남기려면: **10번 후 스파이크 화면을 나가 "말로 하기"로 음성 명령 1회**(= `LlmRuntime.ensureReady()`가 도는 프로덕션 로드, `preferredBackend`=티어) **→ 앱 재시작 → ① 기기 정보 재실행**.
- 스파이크로 받은 모델은 ModelManager의 sha 마커(sqflite)를 남기지 않아 **모델 화면이 "다운로드 필요"처럼 보일 수 있다 — 재다운로드를 누르지 말 것**(2.6GB 재수신). LLM 실행 여부는 flutter_gemma 등록 기준이라 음성 명령 경로는 그대로 동작한다.
- 8번 다운로드 중 앱을 끄지 말 것(첫 측정은 순수 조건으로). **RTL의 Reset Wi-Fi도 8단계 동안 금지**(측정 오염). 실패해도 로그의 `failedAtSec`이 곧 데이터 — 단 저장공간 부족 실패와 9분 타임아웃을 가르려면 §준비의 `df` 기록이 필요하다.
- 10번에서 앱이 강제 종료되면 그것도 결과(OOM) — 기기 RAM과 함께 기록.
- 벤치 프롬프트는 고정되어 있어 기기 간 비교 가능.
